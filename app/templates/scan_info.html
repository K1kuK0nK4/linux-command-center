What does the scan do?

It opens one SSH connection with the server's user, runs a single read-only script and disconnects. It installs nothing, writes no files, downloads nothing and does not use sudo (except for Docker, see below). It takes a few seconds per server. If the user cannot read something, that field is left empty without an error.

Also, the first time it saves the server's SSH fingerprint . If it changes, it will not connect again until you confirm it. By comparing with the previous scan it works out the package changes: installed, updated and removed.

Containers and sudo: Docker usually needs root. First it tries without sudo (if the user is in the dockergroup); if that is not possible, sudo is used (without a password or with the server's sudo password) only to list containers and read their inventory. It is recorded in the Audit log and in the server's log. Only running containers are entered and nothing inside is ever modified.
